什麼是 n8n？

n8n（讀作 "nodemation"）是一個開源的工作流自動化工具，讓你可以用視覺化的方式把不同的應用程式和服務串連在一起。你可以把它想像成一個「數位助理」——當某件事發生時（例如收到一封信），自動幫你做一連串的事（例如存到表格、發通知、回覆訊息）。

它最大的特點是可以自己架設（self-hosted），不像 Zapier 或 Make 只能用他們的雲端服務。這代表你的資料完全掌握在自己手上，也沒有執行次數的限制。

三種安裝方式

n8n 提供三種安裝方式，我們在課堂上推薦使用 Docker，因為它最乾淨、可重複、不會弄亂你的電腦環境。

方式一：Docker（推薦）

只需要安裝 Docker Desktop，然後執行一行指令：

# 最簡安裝（開發用）
docker run -it --rm \
  --name n8n \
  -p 5678:5678 \
  -v n8n_data:/home/node/.n8n \
  n8nio/n8n

# 打開瀏覽器 → http://localhost:5678

如果想要資料持久化（重啟不丟資料），推薦使用 docker-compose.yml：

# docker-compose.yml
version: '3.8'
services:
  n8n:
    image: n8nio/n8n
    restart: always
    ports:
      - "5678:5678"
    volumes:
      - n8n_data:/home/node/.n8n
    environment:
      - N8N_BASIC_AUTH_ACTIVE=true
      - N8N_BASIC_AUTH_USER=admin
      - N8N_BASIC_AUTH_PASSWORD=changeme123
volumes:
  n8n_data:

# 啟動
docker compose up -d
# 查看 log
docker compose logs -f
參考來源：n8n 官方 Docker 文件

方式二：npm

需要先安裝 Node.js 18 以上版本：

# 確認 Node 版本
node -v  # 須 >= 18

# 全域安裝
npm install n8n -g

# 啟動
n8n start

# 或用 npx 免安裝直接跑
npx n8n
macOS 權限問題？用 mkdir ~/.npm-global && npm config set prefix '~/.npm-global' 然後把 ~/.npm-global/bin 加到 PATH。
參考：n8n 官方 npm 文件
方式三：n8n Cloud

如果不想自己架設，可以直接使用 n8n 官方提供的雲端服務。到 app.n8n.cloud/register 註冊帳號，提供免費試用期，不需信用卡。Cloud 版本的好處是自動更新、自動 SSL、不需要管理伺服器，但缺點是有執行次數限制（付費制）。

核心概念：Node（節點）& Connection（連線）

n8n 的一切都圍繞兩個概念：Node 和 Connection。

Node（節點）是 Workflow 的基本單位，每個 Node 代表一個動作。例如「接收 Webhook」、「呼叫 API」、「判斷條件」都是一個 Node。Node 分兩大類：

  • Trigger Node（觸發節點）：Workflow 的起點，決定「什麼時候啟動」。例如 Manual Trigger（手動觸發）、Schedule Trigger（定時觸發）、Webhook（接收外部請求）
  • Action Node（動作節點）：Workflow 的執行步驟，決定「做什麼事」。例如 Edit Fields（編輯欄位）、HTTP Request（發送 HTTP 請求）、IF（條件判斷）

Connection（連線）決定資料的流向。從 A 節點的輸出端拉一條線到 B 節點的輸入端，表示 A 的結果會傳給 B 處理。

動手做：建立第一個 Workflow

實作步驟（跟著做）

  1. 打開 n8n：瀏覽器開啟 http://localhost:5678，首次使用需建立帳號
  2. 建立新 Workflow：點左上角 + 或按 Ctrl+Alt+N
  3. 加入 Trigger：點畫布中央的 +，選擇 Manual Trigger
  4. 加入 Edit Fields：點 Manual Trigger 右邊的 +，搜尋 Set（或 Edit Fields）
  5. 設定欄位：在 Edit Fields 裡加兩個欄位：
    - Name: greeting，Value: Hello, n8n!
    - Name: timestamp，Value: 切換成 Expression 模式，輸入 {{ $now.toISO() }}
  6. 執行：點上方的 Execute Workflow 按鈕
  7. 查看結果：點 Edit Fields 節點，在右側看到 Output 包含 greeting 和 timestamp
  8. 儲存：把 Workflow 改名為「My First Workflow」，按 Ctrl+S
匯出與匯入 Workflow JSON

每個 n8n Workflow 本質上就是一份 JSON 檔案。你可以把它下載下來保存，也可以從 JSON 檔案匯入。

匯出：點擊上方工具列的三個點 ... → Download，會下載一個 .json 檔案。

匯入：點擊 ... → Import from File，選擇 JSON 檔案即可。也可以直接在畫布上按 Ctrl+V 貼上 JSON。

理解 JSON 結構是後續所有章節的基礎。以下是我們剛才做的 Workflow 完整的 JSON：

關鍵知識：Workflow JSON 結構解析

欄位類型說明
name字串Workflow 的顯示名稱
nodes陣列所有節點的清單。每個節點有 id, name, type, position, parameters
connections物件節點間的連線。key 是來源節點名稱，value 描述它連到哪個節點
active布林此 Workflow 是否已啟用（true = 自動執行）
settings物件全域設定，如 executionOrder

nodes 陣列中每個節點的結構：

  • type — 決定這個節點是什麼功能（如 n8n-nodes-base.manualTrigger）
  • parameters — 這個節點的設定參數（如欄位名稱、API URL 等）
  • position — 在畫布上的 XY 座標，純粹用於視覺排列

connections 的結構：

  • "來源節點名": { "main": [ [ { "node": "目標節點名" } ] ] }
  • main 陣列的第一層 = 輸出端口（大部分節點只有一個，IF 節點有兩個：true/false）
  • 第二層 = 連到的目標節點（可以同時連到多個節點）
ch1-hello-world.json — 第一個 Workflow 完整範例下載 JSON
{
  "name": "Ch1 - Hello World",
  "nodes": [
    {
      "id": "trigger-001",
      "name": "Manual Trigger",
      "type": "n8n-nodes-base.manualTrigger",   // 節點類型決定功能
      "typeVersion": 1,
      "position": [250, 300]              // 畫布上的位置 [x, y]
    },
    {
      "id": "set-001",
      "name": "Edit Fields",
      "type": "n8n-nodes-base.set",
      "typeVersion": 3.4,
      "position": [470, 300],
      "parameters": {                       // 節點的設定參數
        "assignments": {
          "assignments": [
            { "name": "greeting",  "value": "Hello, n8n!", "type": "string" },
            { "name": "timestamp", "value": "={{ $now.toISO() }}", "type": "string" }
          ]
        }
      }
    }
  ],
  "connections": {
    "Manual Trigger": {                   // 來源節點名稱
      "main": [[                            // main[0] = 第一個輸出端口
        { "node": "Edit Fields", "type": "main", "index": 0 }
      ]]
    }
  },
  "active": false,
  "settings": { "executionOrder": "v1" }
}

n8n 的資料結構：一切都是 items 陣列

這是 n8n 最重要的概念，也是初學者最容易搞混的地方：在 n8n 中，所有在節點之間傳遞的資料都是一個「陣列」（Array），陣列裡的每一個元素叫做一個「item」。

每個 item 長這樣：

資料結構圖解

[                                    // ← 整體是一個陣列
  {                                  // ← 第 1 筆 item
    "json": {                       // ← 所有文字/數值資料都在 json 裡
      "name": "Alice",
      "email": "alice@example.com"
    }
  },
  {                                  // ← 第 2 筆 item
    "json": {
      "name": "Bob",
      "email": "bob@example.com"
    }
  }
]

關鍵規則：

  • 資料永遠是陣列，即使只有一筆也是 [{ json: {...} }]
  • 每個 item 的實際資料放在 json 這個 key 裡面
  • 如果有檔案（圖片、PDF），會放在 binary key 裡
  • 當一個節點輸出 3 筆 items，下一個節點就會對每一筆分別執行一次
參考：n8n 官方 - Data Structure、Level Two 課程 - 資料結構
表達式（Expressions）：動態引用資料

表達式讓你在節點參數裡動態地引用來自前面節點的資料。語法是 ={{ JavaScript 表達式 }}，注意開頭的 = 號不能省略。

表達式完整速查表

用途表達式說明
取得欄位值{{ $json.name }}目前 item 的 name 欄位
巢狀取值{{ $json.user.address.city }}深層存取
中文欄位{{ $json['姓名'] }}有特殊字元時用括號
其他節點{{ $('節點名').first().json.x }}取得指定節點的資料
所有 items{{ $input.all() }}取得輸入的全部 items
目前索引{{ $itemIndex }}0, 1, 2...
當前時間{{ $now.toFormat('yyyy-MM-dd') }}格式化日期
條件判斷{{ $json.score >= 60 ? '及格' : '不及格' }}三元運算子
預設值{{ $json.name || '匿名' }}如果為空就用預設值
字串轉大寫{{ $json.name.toUpperCase() }}JavaScript 方法都可用
數學運算{{ $json.price * 1.05 }}加稅計算
陣列合併{{ $json.tags.join(', ') }}"紅, 藍, 綠"
Workflow ID{{ $workflow.id }}Workflow 的唯一識別碼
執行模式{{ $execution.mode }}"test" 或 "production"
環境變數{{ $env.API_KEY }}需管理員啟用
常見錯誤：忘記加 = 號。正確寫法是 ={{ $json.name }}，不是 {{ $json.name }}（少了等號不會生效）。另一個常見錯誤是字串與數字搞混："5" + "3" 會得到 "53"（字串串接），要用 Number($json.price) 轉換。
參考：n8n Expressions 文件、n8n 表達式速查表（3200+ 表達式）
三種觸發器

Schedule Trigger 定時觸發

按照設定的排程自動執行 Workflow。Workflow 必須是啟用（Active）狀態才會自動觸發。

常見 Cron 排程：

排程Cron 表達式
每 5 分鐘*/5 * * * *
每天早上 9 點0 9 * * *
每週一早上 8 點0 8 * * 1
工作日每小時 9-17 點0 9-17 * * 1-5
每月 1 號午夜0 0 1 * *
Cron 格式：分 時 日 月 週幾。* = 每個、*/n = 每隔 n、1,15 = 在 1 和 15。
參考：Schedule Trigger 文件

Webhook Trigger 接收外部請求

建立一個 HTTP 端點（URL），讓外部服務可以呼叫來觸發 Workflow。

兩種 URL：

  • Test URL：只在你點「Listen for test event」時有效，適合開發
  • Production URL：Workflow 啟用後永久有效，用於正式環境

支援的 HTTP 方法：GET、POST、PUT、PATCH、DELETE、HEAD

輸出資料包含：headers（請求標頭）、query（URL 參數）、body（請求主體）

參考：Webhook 文件

什麼是 REST API？（給完全不懂的人）

想像你去一家餐廳。你不會自己走進廚房做菜，而是跟服務生點餐。服務生去廚房拿菜，然後端回來給你。API 就像那個服務生——它是應用程式之間溝通的橋樑。

REST API 用 HTTP 方法來表達你想做什麼：

HTTP 方法 = CRUD 操作

HTTP 方法動作類比範例
GET讀取「我要看菜單」取得使用者清單
POST新增「我要點一份牛排」建立一筆新訂單
PUT / PATCH修改「牛排改七分熟」更新使用者 email
DELETE刪除「取消那份牛排」刪除一筆訂單

API 回傳的資料通常是 JSON 格式——跟 n8n Workflow 的格式一樣！

延伸閱讀：從日常生活理解 RESTful API（中文）

HTTP 狀態碼速查

狀態碼意思你該怎麼做
200 OK成功繼續處理回傳的資料
201 Created建立成功新資源已建立
400 Bad Request請求格式錯誤檢查你的 JSON 或參數
401 Unauthorized身份驗證失敗檢查 API Key / Token
403 Forbidden沒有權限確認 API Key 的權限範圍
404 Not Found找不到資源確認 URL 是否正確
429 Too Many Requests請求太頻繁降低頻率，或加 Wait 節點
500 Server Error伺服器錯誤不是你的問題，稍後重試
IF 節點：是非題分流

IF 節點把資料分成兩條路：符合條件的走 true（上路），不符合的走 false（下路）。

每個條件有三個部分：左邊值（要檢查的資料）、運算子（怎麼比）、右邊值（比較對象）。可以設多個條件，用 AND（全部要符合）或 OR（任一符合即可）串接。

Switch 節點：選擇題分流

當分支超過兩條時，用 Switch 節點。它可以有無限多個輸出路徑，類似程式語言的 switch-case。

重要公告：LINE Notify 已於 2025/3/31 停止服務

LINE Notify 在 2025 年 3 月 31 日正式終止服務。所有 Token 失效，API 不再回應。本課程使用 LINE Messaging API 作為替代方案。它功能更強大，支援雙向互動，免費方案每月 200 則推播。
參考：LINE Notify 停止服務替代方案比較
LINE Messaging API 完整設定（從零開始）

LINE Messaging API 是 LINE 官方提供的 API，讓你的程式可以主動發訊息給 LINE 使用者。以下是完整的設定步驟：

Step 1：建立 LINE 官方帳號

  1. 前往 LINE Official Account Manager
  2. 點擊「建立帳號」，用你的 LINE 帳號登入
  3. 填寫帳號名稱（如「n8n 課程通知」）、選擇業種
  4. 完成後會進入管理後台

Step 2：啟用 Messaging API

  1. 在管理後台左側選單，點「設定」→「Messaging API」
  2. 點「啟用 Messaging API」
  3. 第一次使用會要你到 LINE Developers Console 註冊開發者資料
  4. 選擇或建立一個 Provider（注意：建立後無法更改）
  5. 確認後，你的官方帳號就會自動連結一個 Messaging API Channel
注意：2024 年 9 月起，你不能直接在 LINE Developers Console 建立 Channel。必須先建立官方帳號，再從官方帳號管理後台啟用 Messaging API。

Step 3：取得 Channel Access Token 和 User ID

  1. 前往 LINE Developers Console
  2. 選擇你的 Provider → Messaging API Channel
  3. 在「Messaging API」分頁最下方，點「Issue」產生 Channel Access Token（長期有效）
  4. 在「Basic Settings」分頁最下方找到 Your user ID（以 U 開頭的字串）
  5. 這兩個值就是你在 n8n 中需要填入的憑證

n8n-as-code 代碼化管理

CLI 安裝、JSON 轉 TypeScript、Git 版控、AI Skills 搜尋系統

4 小時
▼
為什麼要把 Workflow 變成程式碼？

到目前為止，我們都在 n8n 的圖形介面裡操作。但當你的 Workflow 越來越多、越來越複雜，或需要跟團隊協作時，純圖形操作就會遇到問題：

  • 沒有版本控制：不小心改壞了找不回來
  • JSON 不好讀：幾百行的 JSON 很難一眼看懂修改了什麼
  • 無法 Code Review：團隊成員無法審查彼此的修改
  • 沒有驗證機制：匯入前無法確認 Workflow 是否合法

n8n-as-code 解決了這些問題。它是一個開源工具，把 n8n 的 JSON Workflow 轉換成可讀性更高的 TypeScript 格式，然後用 Git 來做版本控制。

n8n-as-code 四大元件

元件用途
n8nac CLI核心命令列工具：pull / push / convert / list
@n8n-as-code/transformerJSON ↔ TypeScript 雙向轉換器
@n8n-as-code/skillsAI 知識庫：537 個節點 schema + 7,702 個社群模板，本地搜尋
VS Code Extension視覺化介面 + 側邊欄 + 嵌入式畫布

設定步驟

  1. 啟用 n8n API：在 n8n 的 Settings → API，點「Create an API Key」，複製 key
  2. 初始化：npx --yes n8nac init，依序輸入 n8n URL 和 API Key
  3. 選擇專案：選擇要同步的 n8n 專案，設定本地同步資料夾

JSON → TypeScript 對照範例

// ===== 原始 JSON =====
{ "name": "Slack Notifier", "active": true,
  "nodes": [
    { "name": "Webhook", "type": "n8n-nodes-base.webhook",
      "parameters": { "path": "/notify", "method": "POST" } },
    { "name": "Send Slack", "type": "n8n-nodes-base.slack",
      "parameters": { "channel": "#alerts", "text": "={{ $json.message }}" } }
  ],
  "connections": { "Webhook": { "main": [[{ "node": "Send Slack" }]] } }
}

// ===== 轉換後 TypeScript =====
import { workflow, node, links } from '@n8n-as-code/transformer';

@workflow({ name: 'Slack Notifier', active: true })
export class SlackNotifierWorkflow {

  @node({ name: 'Webhook', type: 'n8n-nodes-base.webhook' })
  Webhook = { path: '/notify', method: 'POST' };

  @node({ name: 'Send Slack', type: 'n8n-nodes-base.slack' })
  SendSlack = { channel: '#alerts', text: '={{ $json.message }}' };

  @links()
  routing() { this.Webhook.out(0).to(this.SendSlack.in(0)); }
}

TypeScript 版本更容易閱讀、Git diff 更乾淨、AI 更容易理解和修改。
